# v14 から共通化した教訓

2026-09-22時点のv14のREADME、現在の描画コード、目・口・下地・脚・髪・継ぎ目のビルド／チェック処理を照合した記録です。v14の元プロジェクトは編集していません。

| v14で判明した問題 | ChibiRigKitへの反映 | 確認方法 |
| --- | --- | --- |
| JSONとHTML内データが別々に更新される | ビルドを単一経路にし、埋め込みデータの一致を検査。タイトルとJSONのHTML埋め込みもエスケープ | `validate_character.py`、回帰テスト |
| 閉眼時に開眼の線が残る／閉眼位置がずれる | `closed_part`で対応づけ、同じ支点・親・動きを共有。完全閉眼では開眼を0にする | 48組合せ、終端opacity・行列一致 |
| 放射状メッシュという名前だけで帯状描画になっていた | α輪郭から半径を作り、4重48方向の三角形を閉眼曲線に変形。三角形の反転を防止し、重なりの透明度は1回だけ適用 | 三角形の符号・メッシュ表示 |
| 口の開閉が透明度だけで、中間形状がない | `mouth_open_close`で閉じ口の位置・幅・傾斜へ連続変形。閉じ口は元画像を剛体表示 | 目との独立性・口の中間描画 |
| 頬が瞬き／表情で消える | blushのopacityを目・口・表情に連動させない。必要なら独立マスクで顔グループに所属 | runtimeチェック |
| 下地に髪・腕・脚が残って二重になる | AUTO_RIG_TASKに静止下地の除外条件を明記し、毎回 `base_only.png` をレビュー | 下地表示＋目視 |
| 前髪に肌、髪にフリル、脚に反対側の靴が混ざる | 輪郭・意味領域のマスクレビューを必須化。`texture_repair.file/mask`で指定領域だけを補修 | 原色・領域外不変テスト＋目視 |
| 足先まで境界を補完し、暗いにじみが出る | `seam.file/mask`を関節だけに指定。元絵のシルエット外を除外し、現在フレームの輪郭でさらにクリップ | AI切替・下地不変・残像チェック |
| 補完画像が動きから遅れ、古い補完を混ぜる | 準備済み画像をビルドで埋め込み、パーツと同じ変形で毎フレーム描画。推論キューなし、フレームごとにクリア | 時刻を往復して画素一致 |
| 表情が異なる参照画像で位置合わせが不確か | 完成画像normalを座標基準に変更。特徴点不足時のbbox推定は保証ではなくレビュー対象 | registration.json／source_montage.png |
| 指示だけでは原画像の不変を保証できない | input/alignedをハッシュ記録。自動処理はエージェント呼出し前後を外側でも比較 | 改変時にビルド・自動処理停止 |
| 静止画の一致だけではモーションの品質が分からない | 静止差分とブラウザ検証を分離。量4・16姿勢、残像、終端、初期値復帰を自動確認 | runtime-report.json／runtime_sheet.png |

## 座標とパーツの契約

`pivot`（配列）、メッシュの`center`、`closed_center`、`close_curve.x/y`（オブジェクト）は位置合わせ後のキャンバス座標です。`close_center_y_local`だけは切り出し画像内のローカルY座標です。閉眼カーブは `y + curvature * (x - curve.x)^2`。固定のv14座標や顔の傾きは共通コードに持ち込みません。

開眼に `"closed_part": "eye_left_closed"` を付けると閉眼側は開眼側の変換を共有します。`mouth_smile`を設ける場合は、開口側と同じ `closed_part` と `"transform_from": "mouth_open"` を指定してください。閉眼・閉口は常に元絵の形を保ちます。描画順は各キャラの重なりに従い、対応する閉眼・閉口を開眼・開口の後へ置きます。

`texture_repair` と `seam` は、作業領域に用意したフルキャンバスRGBA画像とLモードの領域マスクを指定します。

```json
{
  "texture_repair": {"file": "work/repairs/hair.png", "mask": "work/masks/hair_repair.png"},
  "seam": {"file": "work/seams/arm.png", "mask": "work/masks/arm_joint.png"}
}
```

補修は元パーツのマスク内だけ。継ぎ目はnormalのα内、明示したマスク内、パーツ切り出し範囲（padを含む）の交差に限定します。補完範囲に必要な`pad`を指定してください。目・口・頬・静止下地への補正は拒否します。通常のリグに補修画像は必須ではありません。

LaMa推論そのものはこの汎用キットには自動移植していません。v14の特定モデル取得・部位別座標を流用せず、準備済み補完画像を受け取る部分を共通化しました。新しい絵柄での補完画像生成と見た目の採否は別工程です。検証数値は意味的な分割の正しさを保証しません。

## 再検証

```sh
source .venv/bin/activate
npm test
npm run test:runtime
```

後者はローカルChromeを使います。別のChromium実行ファイルは`CHROMIUM_PATH`で指定できます。キャラクター単位では、そのディレクトリで以下を実行します。

```sh
python toolbox/build_project.py
python toolbox/validate_character.py
node toolbox/validate_runtime.cjs
```

ヘッドレス起動が利用できない場合は生成される`runtime-check.html`をブラウザで開くと同じ検査を実行します。タイトルがPASSになり、ページ下部にJSON結果と16姿勢の比較画像が表示されます。自動リグ工程はブラウザ検証の失敗を成功扱いにしません。


表示用レイヤーと継ぎ目画像はビルド時の同じスナップショットをHTML/JSONへ埋め込みます。外部PNGだけを書き換えても表示には混ぜません。更新後は必ず再ビルドしてください。検証時には外部ファイルのSHA-256も照合します。
